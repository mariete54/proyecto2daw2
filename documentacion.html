Documentación del frontend

Estructura del proyecto.

Esta página documenta la arquitectura del proyecto BarberFlow. Explica qué hace cada archivo, las etiquetas HTML5 utilizadas, la estructuración del CSS Mobile-First y la lógica de JavaScript implementada.

📄 Archivos HTML

🏠

index.html Dashboard

Página principal. Muestra el saludo personalizado (leyendo el nombre de `localStorage`), la tarjeta de la próxima cita y los accesos rápidos. Usa <main>, <section> y <nav>.

🔐

login.html / registro.html Acceso

Páginas de autenticación. Tienen un diseño dividido con una sección hero y un formulario. Al enviar el formulario de registro, se guarda el nombre en el navegador para personalizar el resto de la app.

📅

crear.html Inserción

Formulario para crear una nueva reserva. Usa inputs tipo `radio` para seleccionar servicio, día y hora. Un <aside> muestra el resumen que se actualiza dinámicamente con JS.

🕐

mis-citas.html Listado

Listado completo de todas las citas reservadas. Lee el array de `localStorage` y genera una tarjeta por cada una. Incluye un botón de papelera para eliminar citas erróneas.

✅

detalle.html Ficha

Ficha detallada de la última cita creada. Muestra el código de reserva, la fecha, hora y servicio. Permite cancelar la cita o crear una nueva.

👤

perfil.html Usuario

Muestra los datos del cliente. El botón "Editar datos" desbloquea los campos para cambiar el nombre. Al guardar, el nuevo nombre se actualiza en toda la aplicación.

✦

planes.html Suscripción

Muestra los planes Esencial, Flow y Signature. El plan activo se marca con un borde dorado. Al hacer clic en otro plan, se guarda la elección y se actualiza la interfaz.

🏗️ Estructura HTML5 Semántica

El proyecto hace un uso estricto de las etiquetas semánticas de HTML5, evitando el uso excesivo de <div>:

  • <header>: Para la cabecera superior (en móvil y login).
  • <nav>: Para agrupar los menús de navegación (sidebar, bottom-nav, pestañas).
  • <main>: Envuelve el contenido principal de cada página (solo uno por documento).
  • <section>: Para agrupar bloques temáticos (panel hero, pasos de reserva).
  • <article>: Para contenido independiente (ficha de detalle, tarjetas de planes).
  • <aside>: Para barras laterales y el panel de resumen de la reserva.

🎨 CSS3 Mobile First

El archivo css/styles.css sigue la filosofía Mobile First:

  • Variables CSS (:root): Colores, tipografías, espaciados, radios y sombras centralizados.
  • Flexbox: Para alinear elementos en una dimensión (menús, botones, tarjetas).
  • CSS Grid: Para crear cuadrículas bidimensionales (planes, citas, reservas).
  • Media Queries:
    • ≥ 640px: 2 columnas en tarjetas.
    • ≥ 768px: Login horizontal. 3 columnas.
    • ≥ 1024px: Aparece la barra lateral (sidebar) y desaparece el menú inferior móvil.

⚙️ Lógica JavaScript y Persistencia

JavaScript Vanilla organizado en la carpeta js/ (scripts clásicos con defer):

  • mockData.js: base de datos simulada (usuario, servicios, barberos, horarios, citas y planes).
  • app.js: núcleo compartido: capa de datos sobre localStorage, fechas, modal, toast, menú hamburguesa y tarjeta de cita.
  • validation.js: validador reutilizable con mensajes en el DOM y validación en tiempo real.
  • pages/*.js: un script por página (dashboard con buscador y filtros, reserva, perfil, planes…).
  • Claves guardadas: bf_usuario, bf_citas, bf_plan, bf_ultimaCita.

La memoria técnica completa está en el archivo MEMORIA.md del repositorio.
